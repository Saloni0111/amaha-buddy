# AmahaBuddy

A conversational agent that helps someone figure out what kind of support they might
need — self-help content, coaching, therapy, psychiatry, or immediate crisis
resources — through a short, empathetic intake conversation.

This is not a diagnostic tool and does not replace clinical judgment. It is a triage
step: understand enough, safely, to point someone toward a sensible next step.

## Architecture

```
User message
     |
     v
Safety check (runs every turn, independent of everything else)
     |                                   \
     | (no risk signal)                  v
     |                          Crisis resources (interrupts immediately)
     v
Orchestrator (tracks state: topic, severity, turn count)
     |                              \
     v                               v
Claude LLM (reply +          Routing (matches to
extract signals via tool)     service taxonomy)
     |                              |
     +--------------+---------------+
                     v
        Recommendation (next step, with reasoning)
```

**Why it's built this way:**

- **Safety check is independent and always-on.** Crisis detection does not live
  inside the conversational LLM call — it's a separate, deterministic check that runs
  on every user message before anything else. Trusting a single LLM call to notice
  and act on risk signals mid-conversation is fragile. This layer is intentionally
  biased toward over-triggering: a false positive costs a moment of "I'm fine, keep
  going"; a false negative could cost much more.

- **Explicit structured state, not just raw chat history.** The orchestrator tracks
  `topic`, `severity`, and `ready_to_route` as real fields (see `agent/state.py`),
  extracted via tool-calling each turn (see `agent/llm.py`, using Gemini's function
  calling). This makes the agent's decisions legible and testable, instead of an
  opaque "the model decided to say this."

- **Routing is separate from generation.** The final recommendation is matched
  against an actual (if small, for this demo) service taxonomy in `agent/taxonomy.py`,
  not freely generated by the LLM. This keeps recommendations grounded and
  traceable — the agent can't recommend a service that doesn't exist.

- **Recommendations always include reasoning**, not just a label — for user trust,
  and because it gives a debugging surface when reading eval transcripts.

## Features

- Open-ended, adaptive intake (no rigid form)
- Always-on, independent safety/crisis layer
- Structured state tracking via Gemini tool-calling
- Taxonomy-based routing with visible reasoning
- Eval suite with saved transcripts across 7 scenarios (see `evals/`)
- No persistent storage of conversation content beyond the session

## Model / API

Uses Google's Gemini API (`gemini-2.5-flash`) via the `google-genai` SDK, on
Google's free tier -- no billing account required. Get a key at
[aistudio.google.com](https://aistudio.google.com), no credit card needed.
Note: free-tier usage may be used by Google to improve their models; avoid it for
anything with real user data beyond this demo/eval context.

## Running locally

```bash
pip install -r requirements.txt
cp .env.example .env   # add your GEMINI_API_KEY
export $(cat .env | xargs)
streamlit run app.py
```

## Running the evals

```bash
export GEMINI_API_KEY=...
python evals/run_evals.py
```

This runs 7 scripted conversations (mild stress, burnout, grief, relationship
conflict, an intentionally vague one, and two crisis scenarios — one direct, one
appearing mid-conversation) against the real agent and writes full transcripts +
pass/fail results to `evals/results/`.

## Known limitations / future improvements

- **Routing** uses lightweight keyword/stem overlap for this demo. Production should
  use real embeddings over Amaha's actual service catalog with a proper vector store.
- **Safety detection** is a keyword-based classifier here. Production should use a
  more robust, clinically-reviewed classifier, ideally tuned with Amaha's clinical
  team rather than an engineer's best guess at keywords, plus a secondary model pass
  for ambiguous phrasing.
- **No human-in-the-loop escalation** — a real deployment should route high-risk
  conversations to an actual counselor queue, not just static helpline numbers.
- **No persistent memory across sessions** — could be added with explicit user
  consent and clear data controls.
- **English only** — multilingual support (especially Hindi and other Indian
  languages) would matter a lot for the actual user base.
- **No automated regression testing over time** — the eval suite is a fixed set of
  scenarios; a stronger version would track pass rates over model/prompt changes.

## Privacy notes

Conversation content lives only in the Streamlit session state for this demo and is
not persisted to disk or sent anywhere beyond the Anthropic API call itself. A
production version would need explicit data retention policy, encryption at rest for
anything stored, and PII handling reviewed against Amaha's actual compliance
requirements.
